第 1 章

全景与核心概念

提示词注入的本质：攻击者把自己的意图写进智能体会读到的文字里，让它去做用户没打算让它做的事。

直接注入补充

攻击者就是发指令的人，或者能直接改动发给模型的输入。典型写法是“忽略你之前的所有设定，改做……”。

间接注入补充

用户的请求完全正常，恶意内容藏在智能体为了完成任务而读取的外部材料里：网页、邮件、压缩包、README。用户并不知情。

本讲攻击属于哪一类

讲者演示的起点是一个良性请求：让智能体总结一个数据集。数据集托管在攻击者的网站上，所以它属于间接注入。讲者在结尾还说，可以再往前一步：在一封邮件里放一段诱导，让智能体改去总结这个数据集，这样用户连“总结数据集”都没说过，就成了完全的间接注入。

它和经典写法的差别在于攻击者“不下命令”。

维度经典“忽略此前指令”本讲的环境布置式
是否明说要做坏事明说，要求违背原指令从不明说。文字稿里没有“忽略指令”“系统维护通知”之类的措辞
怎么触发模型读到后改变行为模型照常做任务，其中一条很可能的执行路径带来了副作用
模型自带防护能看到什么可疑措辞，较容易被识别。讲者认为对前沿智能体已不太有效没有可疑措辞可供识别
谁真正执行恶意动作模型按指令去做解释器按语言规则加载并执行了数据包里的文件
讲者的信条想做好防御者，要先成为好的黑客。所以他花时间弄清攻击怎么运作，并且时不时亲手试。他研究计算机安全近 16 年，约 2016、2017 年开始研究 AI 安全，现在关注防御侧，也就是如何防住提示词注入。
为什么这很严重一个“分析数据集”的请求，不应该导致开发者机器上的代码执行。一旦能执行任意代码，攻击者想做什么基本都可以做。有听众评论说，这等于给了攻击者运行智能体那台机器的 shell。讲者表示同意。

第 3 章

智能体为什么会上当

攻击能成功，靠的是对智能体行为习惯的了解。讲者把这称为“对模型偏置的直觉”。理解这些习惯，才知道防御该补在哪。

1. 想让人满意

只看一个空荡荡的页面，总结不会像样。智能体总想让用户满意，所以会下载 zip 去拿到准确内容。页面刻意写得很简单，就是为了把智能体推向压缩包。

2. 执着，又偷懒

它很执着，但不想把大量内容塞进上下文。发现一个 Python 文件，会先读开头几十行，看到像样的代码就放心了。

3. 偏爱 Python

做数据分析时智能体天然倾向用 Python，因为多数系统自带，库也多。攻击者据此选了 Python 作为入口。

4. 被“示例”轻推

README 只给一个解码示例，并说明路径相对于解压目录。这在人看来再正常不过。如果写成“必须在该目录里运行”，就会触发模型的警觉。

5. 环境必须真实

讲者的数据来自 2004 年的 ICSI 会议转录公开数据集。他试过让 Codex 生成一个假的物流数据集，Claude 识破了假数据，开始对一切起疑。

6. 噪声做掩护

文件多、体积大，智能体就不会全读。前 700 行是用另一个编码智能体生成的、看似处理 CSV 的陪衬代码，真正起作用的几行在后面。讲者用战斗机放干扰弹来比喻。

讲者说的“上下文”张力智能体必须管理上下文，不然会爆掉。比如 Codex 的工具返回有 token 上限（三四千 token），列一个有一万个文件的目录也只能看到一部分。这对攻击者有利：把东西藏在够复杂的文件结构里，护栏就看不到。
补充：从防御角度看补充上面每一条习惯都对应一个防守点：不凭一个极简页面就下载未知文件；对外部包里的可执行文件不只看开头；不让“示例”决定运行位置；对体积异常大的包提高警惕。第 6 章会汇总。

第 4 章

模块遮蔽：为什么数据包里的文件会被执行

核心是一个很老的编程语言特性。Python 有一批标准库，如果当前目录里恰好有一个文件和标准库模块同名，在这个目录里运行时，解释器会先加载这个同名文件。

动手：导入时到底加载了谁

选择智能体运行分析脚本的方式，看看解释器的查找顺序和结果。这里只演示查找顺序，不涉及任何载荷。

同名文件要做的两件事

① 先做自己的事

在被加载的这一刻，同名文件里的附加逻辑先执行。文字稿里，这些逻辑在文件末尾，大约第 714 到 724 行。

② 再把真东西还回去

文件末尾重新导入真正的标准库，这样智能体写的分析脚本里需要的功能照常工作，不会报错。没有报错，智能体就不会停下来检查。

之所以会走到这一步：数据用编码处理过，智能体写的 Python 会导入编码模块，这个模块在内部又会用到那个被遮蔽的标准库模块。所以触发条件是“智能体在数据包目录里运行了自己写的分析脚本”，不需要智能体去运行数据包里的任何文件。

不只是 Python

讲者说 MATLAB、R、JavaScript、Ruby、Perl 都有类似的模块查找行为，具体细节不同。他没有实测过 Node.js，但很有信心，只要智能体用这些语言分析数据，就可以构造出类似环境。如果任务需要大量正则，还可以偏置智能体去用 Perl。

隔离模式 -I 是什么讲者转述的补丁要求：下载并解压后，不要进入该目录运行 Python，要加 -I 参数。它表示隔离模式，会关掉这种动态模块加载，强制从系统安装目录加载标准库。

第 5 章

Auto Mode 分类器的局限

Auto Mode 本该保护你。它的做法是让另一个更便宜的 LLM 审查主智能体的动作，看有没有异常。但整件事是概率性的，而且很依赖主智能体先产生“证据”。

依赖主智能体给证据

如果主智能体碰巧跑了一个进程列表，发现计算器在运行，这些内容进入分类器的上下文，分类器才可能起疑。主智能体没留意，分类器就没有线索。

下载耗时会暴露

假如附加逻辑里要下载一个很大的文件，耗时很长，智能体会奇怪“刚 import 一个模块为什么有 curl 在跑”。如果瞬间完成，几乎不会被注意。

动手 1：智能体读到第几行

讲者观察到，智能体读 Python 文件时常用 head -n 30 这类方式，只看前 30 行左右。拖动滑块，看它能看到什么。

动手 2：智能体会全读吗

文件少、体积小，智能体就全读；文件多、体积大，它会怕上下文被撑爆，只抽查。下面的阈值是教学用的示意值，不是实测。

28 个
200 KB

讲者举的对照：只有三个约 1 KB 的文件，智能体会直接全读，攻击者就没机会；二十五三十个、每个几百 KB 的文件，智能体会小心地不全读，这正是攻击者想要的。

关于“能不能把依赖都交给便宜模型审查”有听众问，能否把代码执行链上所有依赖都送给便宜模型检查。讲者认为这大体就是 Auto Mode 想做的，但依然受上下文管理限制。关于“开一个分支线程临时污染上下文”的问题：如果是同一个模型同一个上下文窗口，只是消息换了标签，就解决不了污染；如果是完全独立的另一个实例，有数据传递机制，才可以扔掉实例只留摘要。讲者说自己不清楚各家的实现。

第 6 章

厂商的修复与防御思路

问题已向 Auto Mode 团队报告并修复。下面是讲者逆向推测出的修复方式，以及他对这个补丁的评价。

修复做了什么（讲者的理解）

Claude Code 每次启动会话，都会把几段系统提示词注入模型，其中有一段偏环境的部分。Anthropic 据推测是在里面告诉智能体：压缩包可能含恶意代码，下载并解压后不要进入该目录运行 Python，要用 -I 隔离模式，让 Python 只从安装目录加载模块。

厂商没有向他确认具体做法，所以这是他的最佳推断。

讲者的评价：补丁非常具体它只是让 Claude 知道这一种模式。还有很多别的做法，这个补丁覆盖不到。第 4 章说过，别的语言有类似机制；手法也不一定要靠模块加载。

第 7 章

方法论与适用边界

讲者在被问到“怎么想到这种攻击”时，总结了两条原则，也坦率说明了攻击在哪些地方并不稳定。

原则一：环境要尽可能真实

把它看成放进智能体面前的一个对抗环境。现在的智能体很擅长分辨真假，假数据会让它全面起疑。

原则二：微妙地偏置，不直接下令

不要明确叫它做坏事，那在前沿智能体上已经不太管用。要布置环境，让它很可能走的某条路径带出副作用。例如这里的路径是“分析数据集”，副作用来自 Python 的行为。

这个攻击形式最早由研究者 wunderwuzzi（文字稿识别为 WonderWuzi）提出，他的博客叫 Embrace the Red。讲者在此基础上找到让攻击更稳定、更通用的办法。

适用边界

情形讲者的说法
Sonnet 和 Opus 系列，多个版本稳定，成功率在九成以上，且智能体没有察觉
Codex（文字稿中提到的 Astra、Sol 等版本）不太稳定，因为它倾向在解压目录之外运行 Python。这只是模型的习惯，不是出于安全考虑。把 README 写得更有说服力，能让它更稳定
能访问一台机器的智能体（讲者称 open claw 风格，编码智能体是其子集）主要目标。它们真的在你的电脑上运行代码
没有电脑访问权限的聊天模式可能不适用，因为没有地方运行 Python。但有电脑权限的办公类智能体符合条件
Fable讲者没有特别测过。他在 Astra 上试过，不稳定，但认为擅长写诱导文字的人可能做到
其他受影响的智能体不能公开，仍在披露流程中

讲者的几个延伸想法

  • 改造成真正的间接注入：让用户去总结一封邮件，邮件里有诱导，把智能体引向攻击者的数据集。
  • 把 README 写得更有说服力，提高在不同智能体上的稳定性。
  • 换用其他语言和其他有模块机制的环境。
  • 他想知道社区在其他地方试出来的结果，也想知道这种攻击在某个比赛场景（文中提到的 IPI 挑战）里算不算有效突破，他自己并不确定。

收尾

总结与自测

先用十条话回顾全篇，再做 12 道综合题。做完会按章节给出回看建议。

十条要点

  1. 提示词注入是把意图写进智能体读到的内容里。本讲攻击的起点是一个良性任务，攻击者从不明说要做坏事。
  2. 攻击链：极简页面诱导下载，压缩包里 README 轻推运行位置，陪衬文件和大体积让智能体只抽查，同名文件在导入时被先执行。
  3. 同名文件执行完附加逻辑后，还会导入真正的标准库，所以分析照常完成，智能体没有报错，也就不会察觉。
  4. 一旦能执行任意代码，就能做任何事：弹计算器只是概念验证，第二段演示把环境变量外泄给攻击者。
  5. 智能体想让人满意，所以会为了准确摘要去下载。它偏爱 Python，也偏爱省上下文，只读文件开头。
  6. 环境必须真实，假数据会被识破。措辞要无威胁，写“示例”，不写“必须”。
  7. Auto Mode 用更便宜的 LLM 审查动作，但是概率性的，依赖主智能体产生证据，也受上下文预算限制。
  8. 厂商修复是在系统提示词里提醒：别进入解压目录运行 Python，用 -I。讲者认为这个补丁非常具体。
  9. 类似的模块查找行为在其他语言里也有，所以只补一种手法不够。纵深防御（沙箱、出站白名单、最小权限）是补充的合理方向。
  10. 两条方法论：环境真实，微妙偏置而不直接下令。防御者要先理解这些偏置。
