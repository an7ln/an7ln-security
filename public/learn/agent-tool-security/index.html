Agent 与工具调用安全：风险与防御

聊天机器人说错话，后果是一段文字。Agent 说错话，后果可能是一封已发出的邮件、一个被删的文件。本页用一个虚构的玩具 Agent「小档」，逐节讲清风险的原理和对应的防御，最后用一个可单步播放的轨迹演示器，看一段被污染的工具结果如何一步步走到数据外泄，又在哪一步被拦住。

受众开发 Agent 的工程师、安全学习者
参考OWASP LLM Top 10（2025）、OWASP Agentic AI 威胁与缓解指南
约定示例只用虚构工具、保留域名 .test 和假密钥，不针对任何真实产品
从第 01 节开始直接看轨迹演示器

// 01Agent 架构与信任边界

规划-工具-记忆-执行Agentic：Memory Poisoning（T1）

本页的主角是「小档」：一个帮你整理文档的玩具 Agent，有四个工具：read_doc、send_mail、run_cmd、fetch_url。它不对应任何真实产品。

Agent 的核心是一个循环：模型规划下一步，调用工具，把结果和历史写进记忆（上下文），再规划，直到任务结束。工具背后是真实的执行环境：文件系统、邮件、命令行、网络。

关键事实：模型把进入上下文的所有文字放在同一条信道里，系统提示、用户消息、网页正文、工具返回之间没有硬隔离。所以信任边界不能只靠“提示词里叮嘱模型”，要画在模型之外，由代码决定什么内容能触发什么动作。

// 02过度授权

OWASP LLM06 Excessive AgencyAgentic：Privilege Compromise（T3）

OWASP 把过度授权（Excessive Agency）拆成三个来源：功能过多（给了任务用不到的工具）、权限过大（工具能碰的范围超过需要）、自主性过高（高影响动作没有人把关）。

过度授权本身不是攻击，而是放大器。无论是提示注入、幻觉还是单纯的误解，一次出错的损失上限等于你给的权限上限。

// 03工具返回内容中的间接提示词注入

OWASP LLM01 Prompt InjectionAgentic：Intent Breaking & Goal Manipulation（T6）

直接注入来自用户本人。间接注入藏在 Agent 读到的内容里：网页、文件、邮件、工单、搜索结果、工具返回值。写这些内容的人并不是你的用户，但文字一旦进入上下文，就和真正的指令挤在同一条信道里。

// 04MCP 生态风险（概念层面）

OWASP LLM03 Supply ChainAgentic：Tool Misuse（T2）

通过 MCP 这类协议，Agent 可以接入第三方工具服务。工具的名称、描述、参数说明都会进入模型上下文，模型用它们决定“何时调用、怎么调用”。这些文字对模型来说和系统提示一样有分量，而用户界面常常只显示工具名。下面三类风险只在概念层面说明，用的都是「小档」的虚构工具。

// 05数据外泄风险及缓解

OWASP LLM02 Sensitive Information DisclosureLLM05 Improper Output Handling

数据要离开你的边界，需要一个出站通道。常见的有：客户端渲染 Markdown 时自动加载图片、模型回复里的链接、工具参数（发邮件、请求网址）、代码执行后的网络访问、日志与遥测。

Markdown 图片是最典型的例子：渲染器看到图片语法就会自动发起请求，用户不需要点任何东西。如果被污染的上下文让模型把一段数据拼进图片地址，数据就跟着请求出去了。

// 06多 Agent 之间的信任传递

  
Agentic：Communication Poisoning（T12）Rogue Agents（T13）

  

    
多个 Agent 协作时，很容易默认“同事说的话可信”。但消息里的内容可能源自某个网页，只是被上游 Agent 复述了一遍。污染沿消息链传播，每转手一次，来源信息就少一层，最后一个 Agent 看到的是一句语气自然的“请求”。

    
这就是经典的混淆代理问题：下游 Agent 手里有真实权限，却被一个没有权限的来源借用了。

// 07高风险工具的权限设计

  
Agentic：Unexpected RCE（T11）LLM06

  

    
shell、文件、网络请求是三类最需要认真设计的工具，因为它们的后果是真实且常常不可逆的。设计时按三个问题走：能做什么（范围）、在哪里做（隔离）、谁来批准（确认）。

  

  

    
工具主要风险更安全的默认值

    
      
run_cmd任意命令执行、凭据读取、横向移动命令白名单 + 沙箱（无网络、只读根）+ 超时与资源配额

      
read_doc / write_doc读取密钥、路径穿越、覆盖或删除文件限定根目录并规范化路径；读写分开授权；写前展示 diff

      
fetch_url访问内网、把数据放进请求发出去、拉回新的注入内容域名白名单，只出站 GET；拦截内网与元数据地址；返回内容按不可信处理
